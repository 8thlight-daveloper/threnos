# Issue sizing examples

Copy this file to `docs/reference/issue-sizing.md`. The `writing-issues` skill
sizes an issue by what a person must review to accept it. The skill's own table
shows the shape. Replace each example below with a finished issue from this
project, so a new size call has a local reference.

| Size | Example from this project |
| -- | -- |
| XS | <issue or change that touched two files or fewer, with no new behavior> |
| S | <one decision, one small contract, or one build of a small contract> |
| M | <one larger contract draft or hardening pass, or its build> |
| L | <an issue that was filed too big, and how it should have been split> |
| XL | <an epic, with the leaf issues under it> |
